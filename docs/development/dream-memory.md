# Dream 与分层记忆

## 目标

SA 的记忆系统不是“把更多内容长期保存下来”，而是通过 dream 不断提炼长期记忆，让 Agent 随时间增长，但不被噪声淹没。

核心目标：

- 保留原始经历，确保可追溯
- 只把高价值、稳定、可复用的信息提升为长期记忆
- 定期去重、去噪、修正冲突
- 从经历中抽象出协作规律、偏好与经验教训

## 三层结构

### 1. 原始层

原始层保留未经提炼的经历与过程信息：

- `sessions/*.jsonl`
- `memory/YYYY-MM-DD.md`

职责：

- 记录真实过程
- 保留完整证据链
- 为后续 dream 提供原料

特点：

- 可以杂乱
- 可以包含短期上下文与一次性细节
- 不直接等同于长期记忆

### 2. 长期层

长期层保存经过提炼、未来仍然有价值的知识：

- `MEMORY.md`
- `memory/topics/*.md`

职责：

- 保存稳定偏好
- 保存长期目标
- 保存跨会话可复用的约束、规则、经验
- 为未来会话快速定向

写入原则：

- 只有当信息高价值、稳定、可复用时才进入长期层
- 旧记忆若被新证据推翻，应直接修正或删除
- 长期层追求高密度，不追求数量

### 3. 提炼审计层

提炼审计层保存每次 dream 的治理记录：

- `memory/dreams/*.md`

职责：

- 记录本次 dream 看了哪些来源
- 记录哪些内容被提升为长期记忆
- 记录哪些重复项被合并
- 记录哪些噪声被删除
- 记录哪些冲突被修正

注意：

- `memory/dreams/*.md` 是审计记录，不是普通记忆搜索的主来源
- 普通 MemorySearch 不应优先返回 dream 审计文件

## Dream 的本质

dream 不是 nightly summary。

dream 的职责是长期记忆治理：

- 去噪：过滤一次性、低价值、短期信息
- 去重：合并重复记忆
- 修正：发现并修复相互冲突的旧记忆
- 抽象：把经历提升为规则、偏好、经验教训
- 压缩：让长期记忆更精炼、更高密度

因此，dream 更像“记忆整理与反思”，而不是“把今天发生了什么再说一遍”。

## 调度策略

当前实现：

- 使用本地时区
- 每天本地 `00:00` 自动触发一次 dream
- 后端启动后，如果当天还没有成功 dream，则会立即补跑一次
- 使用 `memory/.dream.lock` 防止重入
- 使用 `memory/.dream-state.json` 保存最近一次成功日期与审计输出路径

## 输入源选择

每次 dream 会优先读取：

- `MEMORY.md` 或 `memory.md`
- 最近的 `memory/topics/*.md`
- 最近几天的 `memory/YYYY-MM-DD.md`
- 最近若干 `sessions/*.jsonl`

目标不是穷举所有历史，而是在有限上下文中获取最可能影响长期记忆质量的信号。

## 梦境任务输出

dream 任务需要完成三类输出：

1. 更新 `MEMORY.md`
2. 更新或新建 `memory/topics/*.md`
3. 写入当日审计文件 `memory/dreams/YYYY-MM-DD.md`

如果本次没有发现值得提升或修正的长期记忆，也需要写审计文件，明确说明“本次未发现需要更新的长期记忆”。

## 与普通记忆检索的关系

普通对话中的检索优先级应为：

1. `MEMORY.md`
2. `memory/topics/*.md`
3. `memory/YYYY-MM-DD.md`
4. `memory/dreams/*.md`（仅在需要审计 dream 过程时）

当前 `MemorySearch` 会检索：

- `MEMORY.md`
- `memory.md`
- `memory/*.md`
- `memory/topics/**/*.md`

当前 `MemoryGet` 额外允许显式读取：

- `memory/dreams/**/*.md`

这样可以兼顾：

- 普通会话不被 dream 审计噪声污染
- 需要追责或排查时，仍能精准读取 dream 输出

## 与 compact / session 的关系

`sessions/*.jsonl` 仍然是 SA 的主会话原始记录来源。

compact 负责上下文窗口压缩，dream 负责长期记忆提炼。两者职责不同：

- compact：让当前会话还能继续跑
- dream：让长期记忆越来越强

dream 不会把自己的运行过程写进顶层主会话持久化文件，而是走隔离运行态，避免污染普通会话历史。
